# Nexoraa CleanSoft Implementation Phase Prompts

These prompts are the executable implementation plan for the repository. Run them in numeric order and complete the linked report before starting the next phase. The original scaffold filenames are retained to avoid a repository-structure change; the canonical phase identity is the number and name inside each prompt and in this catalog.

All prompts treat the repository as the single source of truth, require mandatory reading, preserve unrelated changes, constrain out-of-scope work, enforce enterprise architecture/security/testing standards, and end with a factual completion report.

## Execution Rules

1. Start with Phase 00 and proceed only after its acceptance criteria and completion report are verified.
2. Read every mandatory source named by a prompt and inspect current implementation/tests before editing.
3. Never use a completion report as proof when current code, configuration, tests, or deployed evidence contradicts it.
4. Do not begin later-phase features early. A dependency defect may be repaired only as narrowly as necessary and must be disclosed.
5. Preserve service data ownership, tenant/branch isolation, deny-by-default RBAC, precise money, versioned contracts, idempotency, redacted telemetry, and tested recovery throughout.
6. Use [AUDIT_PHASE_PROMPT.md](./AUDIT_PHASE_PROMPT.md) after any phase or before a release gate when independent conformance review is needed.
